# Supply Chain Planning System – Mock Data Schema

## Overview

All datasets are generated by `mock_data_generator.py`.  
Run: `python data/mock_data_generator.py`

---

## 1. `product_master.csv`  — 30 rows × 9 cols
Product catalog. Foundation for all planning layers.

| Column | Type | Description |
|---|---|---|
| `sku` | str | Unique product ID (e.g. SKU-1000) |
| `sku_group` | str | Category: Premium / Standard / Organic / Industrial Sugar |
| `inventory_type` | str | Storage classification |
| `unit_cost_vnd` | float | Unit cost in VND |
| `volume_cbm_per_unit` | float | Volume per unit in CBM (for capacity planning) |
| `weight_kg` | float | Weight per unit |
| `shelf_life_days` | int | Maximum shelf life in days |
| `abc_class` | str | ABC classification (A/B/C) |
| `is_active` | bool | Whether SKU is currently active |

---

## 2. `warehouse_master.csv`  — 7 rows × 6 cols
Warehouse capacity and cost data.

| Column | Type | Description |
|---|---|---|
| `warehouse` | str | Warehouse name |
| `region` | str | Geographic region (North/Central/South) |
| `capacity_cbm` | int | Total storage capacity in CBM |
| `capacity_tons` | float | Total storage capacity in tons |
| `rental_cost_per_month_vnd` | float | Monthly rental cost in VND |
| `is_active` | bool | Whether warehouse is active |

---

## 3. `supplier_master.csv`  — 4 rows × 6 cols
Supplier information for replenishment planning.

| Column | Type | Description |
|---|---|---|
| `supplier_id` | str | Supplier ID (SUP-001 … SUP-004) |
| `supplier_name` | str | Supplier full name |
| `region` | str | Supplier region |
| `reliability_score` | float | Historical reliability (0–1) |
| `min_order_qty` | int | Minimum order quantity |
| `payment_terms_days` | int | Payment terms (days) |

---

## 4. `lead_time.csv`  — 46 rows × 6 cols
Lead times per SKU × Supplier combination.

| Column | Type | Description |
|---|---|---|
| `sku` | str | Product ID |
| `supplier_id` | str | Supplier ID |
| `lead_time_days` | int | Average lead time (days) |
| `lead_time_std_days` | float | Std deviation of lead time (for safety stock) |
| `transit_days` | int | In-transit time (days) |
| `review_period_days` | int | Replenishment review cycle (days) |

---

## 5. `sales_history.csv`  — 30,240 rows × 9 cols
Daily sales data for 180 days. Core input for demand forecasting.

| Column | Type | Description |
|---|---|---|
| `date` | date | Transaction date |
| `sku` | str | Product ID |
| `warehouse` | str | Warehouse location |
| `sales_qty` | int | Actual units sold (after stockout) |
| `demand_qty` | int | True underlying demand (before stockout) |
| `sales_value_vnd` | float | Revenue in VND |
| `is_promotion_day` | bool | Whether a promotion was active |
| `stockout_flag` | bool | Whether stockout occurred |
| `month` | str | Month label (YYYY-MM) |

> **Note:** `sales_qty` may be less than `demand_qty` when `stockout_flag = True`.  
> Forecasting models should use `demand_qty` (true demand) for unbiased estimation.

---

## 6. `inventory.csv`  — 168 rows × 10 cols
Current inventory snapshot (as of last day of history).

| Column | Type | Description |
|---|---|---|
| `snapshot_date` | date | Date of inventory count |
| `sku` | str | Product ID |
| `warehouse` | str | Warehouse location |
| `on_hand_units` | int | Units on hand |
| `unit_cost_vnd` | float | Unit cost in VND |
| `inventory_value_vnd` | float | Total inventory value in VND |
| `used_cbm` | float | Volume occupied (CBM) |
| `inventory_type` | str | Type of inventory |
| `lot_number` | str | Lot/batch number |
| `expiry_date` | date | Expiry date of lot |

---

## 7. `promo_calendar.csv`  — 40 rows × 7 cols
Forward-looking promotion plan. Used to adjust demand forecasts.

| Column | Type | Description |
|---|---|---|
| `promo_id` | str | Unique promotion ID |
| `sku` | str | SKU on promotion |
| `warehouse` | str | Applicable warehouse |
| `promo_start` | date | Start date |
| `promo_end` | date | End date |
| `uplift_pct` | float | Expected demand uplift (%) |
| `promo_type` | str | Price Off / Bundle / Display / Flash Sale |

---

## 8. `cost_parameters.csv`  — 30 rows × 5 cols
Input parameters for inventory optimization models.

| Column | Type | Description |
|---|---|---|
| `sku` | str | Product ID |
| `holding_cost_pct` | float | Annual holding cost as % of unit cost |
| `ordering_cost_vnd` | float | Fixed cost per order (VND) |
| `stockout_cost_per_unit_vnd` | float | Penalty cost per lost unit (VND) |
| `target_service_level` | float | Target service level (0–1) by ABC class |

---

## Data Relationships

```
product_master ──┬── sales_history   (sku)
                 ├── inventory        (sku)
                 ├── lead_time        (sku)
                 ├── cost_parameters  (sku)
                 └── promo_calendar   (sku)

warehouse_master ─── sales_history   (warehouse)
                 └── inventory        (warehouse)

supplier_master ──── lead_time       (supplier_id)
```

## Planning Layer Inputs

| Layer | Primary Inputs |
|---|---|
| **Demand Forecasting** | sales_history, promo_calendar, product_master |
| **Inventory Planning** | lead_time, cost_parameters, product_master |
| **Replenishment** | inventory, lead_time, supplier_master, warehouse_master |
